# Borrow Lab 数据模型

当前实现：Node.js 22.14 的内置 node:sqlite，本机文件 `data/borrow-lab.sqlite`。WAL、外键约束和事务启用，无新增第三方依赖。此文件及备份均被 Git 忽略。

| 表 | 职责与关键约束 |
| --- | --- |
| users | id、name、role、avatar、prefs；偏好含字号、主题和减弱动效 |
| equipment | id、payload；28件/10类初始化快照。当前 API 权威设备源仍是 src/catalog.js，数据库尚未提供设备管理编辑入口 |
| reservations | id、user_id、equipment_id、date、slot、status、payload；有效预约的设备/日期/时段唯一，取消保留历史 |
| favorites | user_id、equipment_id 组合唯一 |
| plans | id、user_id、payload；场景、名称、日期、时段、设备ID和准备状态 |
| achievements | user_id、key、title、created_at；同一里程碑只记一次 |
| metadata | 旧 JSON 导入标记，避免重复迁移 |

HTTP 通过 `src/product-store.js` 的仓储接口读写；原预约约束仍由 `src/booking.js` 校验。`src/creative.js` 计算准备度、真实可用状态和同能力替代，不调用模型。模型只选择库内设备，服务端再次检查时间与ID。准备度表示目标时段可用或已由本人锁定的设备比例，不冒充电量、实际使用或归还评分。

初始化可重复执行：`node scripts/seed-product.js`。不会清空既有数据。首次迁移 `data/reservations.json` 前保存 `.pre-sqlite-backup`，保留原预约ID；导入失败中止。取消预约为软删除，再约创建新记录。

账号切换是本机产品体验：读写以 userId 区分，取消仅限预约归属；这不是可公开上线的真实身份认证。头像限制为本地 PNG/JPEG/WebP、350KB以内，拒绝远程/SVG头像。通知由真实预约/方案动态计算，并未接邮件或系统推送。个人导出为 JSON；预约表既有 CSV 导出继续保留。

关系图、Smart Replace 和场景组合基于规则与台账；能力适配百分比是规则分值，不是模型概率。AI密钥仅在后端环境变量中读取，SQLite不保存密钥。
