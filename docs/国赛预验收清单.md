## 建议按这十项进行第一轮人工检查

1. 首屏加载后搜索“投影”，结果应只包含投影设备；清空搜索恢复三件台账设备。
2. 切换日期和设备，检查时段联动；已结束和已占用的时段不可预约。
3. 用自己的姓名创建未来日期的投影仪下午预约，确认列表显示成功记录。
4. 再次预约同设备、同日期、同时段，应被拒绝；不同设备仍可预约。
5. 勾选“只看我的预约”，只出现所填姓名的记录；取消筛选可恢复完整列表。
6. 取消自己创建的预约，再预约同一时段，应成功；不要取消他人已有记录。
7. 刷新页面，预约状态应保持，设备空闲数量与列表一致。
8. 输入四个指定 AI 问题，与自己当前台账对照；本台账没有同用途投影仪替代品，不应推荐相机/录音笔作为等效替代。
9. 生成七天周报，检查六部分、2～3条建议与实际数量；数据清空后再次生成应明确为空且样本不足。只清理自己创建的验收数据。
10. 观察“正在生成 / 已完成 / 生成失败”，生成中两按钮均禁用；再检查窄屏、键盘焦点和弹窗。网络故障可通过停止本机预览服务后点击 AI 按钮演示，恢复服务后再试。

## 技术证据与验收边界

- 自动化：npm test，36 组通过 / 0 组失败；全部 AI 用 mock，不读取本机 Key，不请求真实模型。
- 真模型：node scripts/check-national-ai.js，仅本人明确运行的本机手动验收；两种周报 + 四个指定问题，共6项通过、0项失败。证据：`docs/验收证据/国赛阶段1-真实AI.json`。
- 页面观察（Codex，本人未验收）：生成中两个AI按钮均禁用；完成后六部分周报可阅读，按钮恢复；暂时停止本机预览服务后，界面显示“生成失败：无法连接本地服务，请检查网络与预览服务是否运行。”，恢复服务后重新生成成功。不是制造真实上游401/429/500，这些异常由mock覆盖。截图：`验收证据/国赛阶段1-周报页面.png`、`验收证据/国赛阶段1-周报建议.png`、`验收证据/国赛阶段1-网络失败.png`。
- 安全检查：实际本机Key在非忽略项目文件和Git差异中均未检出；.env被忽略，HTTP访问/.env、/src/ai.js、/ai-context.js均404。浏览器35秒等待上限，不自动重新提交请求；后端每次上游15秒上限。
- 手动脚本的四条临时预约通过当前业务接口写入本机真实存储，结束后仅取消脚本自己创建的记录；基线恢复为空。临时样例不冒充真实使用历史。
- 模型看到真实设备台账、匿名预约记录、服务端统计和建议候选；预约人姓名与记录 ID 不发送。查询意图由模型解析，结论由服务端完整台账核对。周报事实由服务端生成，建议由真模型选择和排序，不声称全部文字都是模型自由撰写。
- 周报单请求最多两次调用：首轮 max_tokens=1800，唯一重试=2400，总输出预算上限4200；检查 finish_reason=length、空内容、短内容、非法JSON、缺失章节/依据。两次仍不完整返回明确错误。授权、额度、网络、HTTP 非JSON失败不自动重试。
- 每次上游请求15秒超时，查询最多800输出tokens；输入1～300字符。当前单进程每日20次上限，重启计数清零；这不是持久化预算或生产鉴权。
- 本阶段没有做第三阶段 UI 重构、生产部署或未来日期报告；四尺寸完整视觉验收、本人体验验收仍待完成。
