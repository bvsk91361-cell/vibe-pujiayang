## 业务与数据依据

- 正常库 `data/borrow-lab.sqlite`，演示库 `data/demo/*.sqlite`。WAL、外键、busy_timeout=5000；users/equipment/reservations/plans等表已真实读取。初始化只同步设备payload，不清用户/预约/偏好。旧JSON迁移有备份和完整事务，重复占用时拒绝迁移，不静默丢失。
- 唯一索引：`CREATE UNIQUE INDEX active_slot ON reservations(equipment_id,date,slot) WHERE status='active'`。同槽在服务端再次校验；事务锁保护读校验与写入；数据库兜底。取消保留历史并移出active约束。跨进程整套竞争1套成功/1套409，成功套3条，未留下半套。
- 日期存业务标识YYYY-MM-DD，时段为09:00–11:00、14:00–16:00、19:00–21:00；实际createdAt仍ISO时间戳。业务统一Asia/Shanghai，无需迁移日期列。保留原规则：时段结束前可预约，结束瞬间起拒绝；开始前「待使用」，开始后「使用时段中」，不是有领用记录的实际使用证明。
- 身份是本地演示方案，不是公网认证。接口核对传入userId与预约所属身份，但知道他人ID可冒用身份，正式联网需真实认证。本轮不发布。
- 周报窗口是北京时间本周一至周日；热力图窗口是当天起未来7天。两窗口不能直接混比。26件可运营×7日×3时段=546计划容量，维护设备排除。6/546=1.1%只属于10-08 20:56真实生成快照，之后实时重算。
- 预约占用率不是实际使用率。没有领用/归还记录，不推测使用时长；没有冲突失败日志，不编造冲突次数。模型只组织程序算好的事实和有依据建议。
- YOSHUB_API_KEY/BASE_URL/MODEL只在后端环境读取；.env未追踪，HTTP404；真实模型仅本机手动验证，CI默认mock。
