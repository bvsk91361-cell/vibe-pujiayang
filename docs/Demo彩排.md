## 本轮发现并解决

- 首次可见截图中成功标题仍偏左：旧success-card h3继承display:flex；新凭证组件解除旧类继承并统一中心标题，再次截图及浏览器核对通过。
- 热力图图例原与全站empty样式冲突，尺寸被放大；改用组件专属状态名，修正收尾时漏掉的拼接符，再以暗夜浏览器确认图例18px且页面正常。
- 旧缓存凭证只验证ID和用户，未对照实际设备/时间：改为全字段核对并拒绝已取消记录，回归通过。
- 新问法「今天还能预约什么」原会进入模型：补轻量台账路径；「这台设备」缺上下文时要求指定设备，错误输入保留。
- 浏览器专用工具仍报kernel assets路径不存在。已检查服务端口、预置运行时与系统Edge，使用现有Playwright+独立Edge会话完成实际点击，没有安装新框架。
- 浏览器测试中头像检查第一次未选择账户页，第二次在刷新异步渲染完成前断言，属于测试步骤/等待问题；补正确账户入口和等待，裁剪保存/刷新/隔离实际通过，没有将这些测试错误写成产品Bug。

## 演示环境与恢复

日常版本：http://localhost:3004/#workspace。独立演示：http://localhost:3005/#workspace，页面明确标「独立演示数据」。不动日常data/borrow-lab.sqlite。

```powershell
node scripts/demo-day.js
```

这条命令每次生成全新data/demo库，不删除旧库或用户历史。恢复初始状态：在自己启动演示的终端Ctrl+C停止旧实例，再执行同一条命令。端口被占时先核对自己的演示进程，不杀其他服务。继续上次演示则使用 --db 加控制台真实打印路径。

动态日期按运行当天计算；选择明天的有效时段。过去夹具明确demo:true，不声称通过过去日期预约接口产生。营业时段外没有真实「使用时段中」记录，只展示待使用/已到期并补充真实开始结束边界测试；禁止改系统时钟。

## 备用路线

- AI失败：不连续付费重试，明确设备/时间走本地台账；普通预约照常。周报展示已保存真实证据并说清生成时间，不冒充现场在线成功。
- 网络/公网失败：使用3005本地Node+SQLite，旧公网静态版不代表当前后端。
- 剩余时间不足：优先预约→冲突→取消释放；不牺牲老师最关注的业务来展示Hero动画。
- 指代不明/方案时间冲突：指定真实设备或改时间，保留输入与组合，不重新走无关页面。
- 日期失效/演示数据已使用：创建新隔离库，核对身份、日期和可约状态，不清正式数据库。

当前可宣布「技术准备与自动流程验证完成」，不能宣布「本人8分钟彩排完成」。
