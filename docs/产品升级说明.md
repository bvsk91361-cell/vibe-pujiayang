# Borrow Lab 产品升级说明

记录日期：2026-10-07。分支：`feat/glass-review-workspace`。
当前状态：**阶段 A 方案已准备，等待蒲嘉洋确认；B～E 尚未开始。**

定位：面向校园创作与实验场景的设备预约与智能调度平台。
产品承诺：发现合适的设备，确认真实空闲，带着明确安排开始创作。
展示价值来自完整流程、原创视觉、真实台账与可解释的 AI；比赛水平仍需真实使用和评审验证。

## 1. 页面结构

采用共用应用外壳、独立功能视图；桌面顶部导航，移动端精简导航与“更多”入口。保留现有预约/洞察锚点的兼容跳转，不强制重写整套框架。

| 视图 | 首要任务 | 主要模块 |
| --- | --- | --- |
| 首页 / 工作台 | 发现设备并快速预约 | 5 项沉浸式 Hero、快速预约入口、精选设备、6 个创作场景、个人下一条预约、AI 入口 |
| 设备中心 | 找到适合场景且可预约的设备 | 搜索、10 类分类、场景/状态筛选、收藏、设备详情、型号参数与空闲时段 |
| 预约流程 | 少走一步、确认一次 | 设备 → 日期 → 时段 → 确认；桌面右侧摘要，移动端顺序表单；成功卡片、冲突处理 |
| 我的预约 | 看安排、调整安排 | 即将开始 / 已结束 / 已取消；再次预约入口；状态由实际时间和台账计算 |
| 数据洞察 | 理解预约计划和资源分布 | 预约占用率、热门设备、时间分布、真实冲突记录、六部分 AI 周报 |
| 个人中心 | 管理自己的创作空间 | 资料、账号卡片、字体/动效/外观设置、收藏、徽章、提醒、JSON/CSV 导出 |

首页的重点是“设备值得借、现在能不能借、下一步怎么借”。统计图与完整报表在洞察页；个人中心收纳偏好和成就，首屏不堆全部模块。

### 首屏构图与原创文案方向

- 半透明导航悬浮在夜空蓝展示区之上，品牌保留“借一下 · Borrow Lab”。
- Hero 以原创设备主视觉为中心：左侧大标题和简短说明，右侧产品光影，底部设备家族导航。
- 候选主文案：“让好设备，接住你的下一次创作。”主 CTA：“发现可借设备”；次 CTA：“按场景配一套”。最终文字随实际界面调整。
- 5 个展示主题：影像相机、云台相机、航拍设备、无线麦克风、便携投影。点击 CTA 能进入对应设备和真实空闲信息。
- 深色展示区下接冰白/雾蓝工作区，使用清晰留白、边框和信息层级；主内容卡片采用更实的背景以保证阅读。

## 2. 统一设计系统

### 色彩与材质

拟定基础色：夜空蓝 `#0B1424`、深蓝黑 `#070D17`、冰白 `#F6F8FC`、雾蓝 `#E7EEF8`、电光蓝 `#397CFF`、淡紫灰 `#B8B5D9`。
这些是设计候选值，不冒充已经通过对比度测试。实际文本/按钮颜色在 B、D 阶段检查。
玻璃重点用于导航、轮播控制与浮层；表单、报告和设备信息以可读性为先。支持不透明降级，不以强模糊掩盖文字。

### 字号与可访问性

使用系统字体栈，不下载 Apple 专有字体；中文优先本机系统字体。统一 rem 与字号 token，杜绝现有 9～11px 成片正文。

| 级别 | 标准桌面候选 | 移动端处理 |
| --- | --- | --- |
| Display | 56～72px | clamp 收缩至约36～44px，允许自然换行 |
| H1 / H2 / H3 | 40 / 30 / 22px | 按内容与屏宽适配 |
| Body / 表单 / 导航 | 16px，正文行高约1.6 | 保持舒适阅读，不通过缩小文字挤布局 |
| Caption | 13～14px | 只用于次要说明，不承载关键状态 |

个人中心提供标准 / 较大 / 超大三档（初始拟定1 / 1.125 / 1.25倍）。关键正文、导航、表单与卡片随设置变化；另验证浏览器200%缩放，不把三档设置当作完整无障碍认证。
关键触控区域目标至少44×44px。保留明显 focus-visible、语义标签、键盘流程、模态焦点返回和状态播报。

### 动效与反馈

- 常规反馈160～240ms，卡片/浮层220～350ms；优先 transform/opacity，避免布局抖动和连续大范围 blur 动画。
- Hero 使用交叉淡入与轻微位移；轮播初始间隔约7秒，有明确暂停按钮。悬停、键盘焦点进入、页面不可见时暂停；用户手动切换后不强行恢复自动播放。
- `prefers-reduced-motion` 或账号“减弱动画”设置优先：关闭自动轮播、大位移和勾选路径动画，仍保留明确文字反馈。
- 预约按钮状态：待确认 → 保存中（禁重复提交）→ 成功勾选 → 设备/日期/时段成功卡片。只有后端保存成功才播放成功反馈。
- 409冲突：表单就地提示、刷新空闲时段、保留姓名和可用选择；不出现虚假的成功卡片。
- Toast 作为补充，成功卡片持续保留到下一次操作；关键错误不依赖短暂 toast 或颜色。全部避免原生 alert。

## 4. 数据选型与兼容方案

**选择：SQLite + 服务层 + 仓储接口；在阶段 C 切换持久化。**
本机 Node 22.14.0 已实际完成 `node:sqlite` 内存建表、写入和读取，不安装第三方驱动、不修改现有磁盘数据。
该版本 SQLite API 仍有实验性提示；使用基础语句和参数绑定，锁定已验证运行版本。同步读写仅承担本地小规模事务，后续多人部署再评估隔离到 worker/独立数据库。
参考：[Node 22.14 SQLite 官方文档](https://nodejs.org/download/release/v22.14.0/docs/api/sqlite.html)。

调用层次：视图 → HTTP API → 预约/账号/收藏/洞察服务 → 仓储接口 → SQLite。
阶段 B 先建立共用设备台账与适配接口，预约仍用原文件存储；阶段 C 更换仓储实现。数据库导入失败必须明确停止，不能静默创建空库或悄悄切换数据源。

| 模型 | 关键内容 |
| --- | --- |
| users | 稳定id、唯一演示昵称、头像种子、角色标签、字号/动效/外观偏好、创建时间 |
| equipment | 稳定id、分类、型号、参数、能力、兼容关系、素材地址、运维状态、演示标记 |
| reservations | id、user_id、equipment_id、日期、时段、状态、姓名快照、创建/取消时间 |
| favorites | user_id + equipment_id 联合唯一、收藏时间 |
| notifications | 账号、提醒类型、来源预约、已读状态；应用打开时根据实际时间刷新 |
| achievement_logs | 账号、徽章键、触发预约、解锁时间；唯一约束防重复奖励 |
| conflict_logs | 实际被拒绝的设备/日期/时段及时间，不含密钥或请求头；用于真实冲突统计 |

账号切换保存的是本机当前账号 id；设置、收藏和历史按 user_id 隔离，不继续依赖输入姓名来判断归属。预置蒲嘉洋、创作组同学A、创作组同学B、游客体验四个账号；管理员演示标签可选，不赋予真实线上权限。支持新增本地账号，界面清楚标明本地演示模式。

迁移约束：

1. 保留 camera/projector/recorder 的稳定 id 和现有预约id；迁移前备份JSON，先做dry-run与逐条核对，再事务导入。迁移脚本可重复运行，无重复导入。
2. 旧记录按已有姓名明确匹配；无法唯一匹配则创建有标记的历史账号，不把预约默认为当前用户。当前记录含何种字段，迁移前实际检查，不编造取消历史。
3. 取消改为保存已取消状态；原 `/api/reservations` 继续返回有效预约，新历史接口提供已取消记录。现有取消后重约、冲突检测与刷新语义保留。
4. 有效预约的设备/日期/时段使用数据库唯一约束；维护状态和日期规则由服务层校验，约束冲突转为现有409反馈。
5. AI只读取有效匿名预约和同一设备台账；新增设备能力由明确字段描述，取消/维护设备不被误算为空闲或利用率分母。
6. 原36组回归场景保留，三件设备容量63的断言仍用原三件设备夹具；生产28件设备另测实际容量与维护排除。通过依赖注入隔离夹具，不删除断言来掩盖回归。
7. 初始化与seed只补缺失的设备/演示账号，不覆盖用户修改或真实预约；数据库、备份、个人导出和.env均不提交Git。

AI缓存本轮不作为必做：避免旧台账缓存返回假空闲。未来若增加周报缓存，键须包括台账版本、统计窗口、模型和提示版本，并展示生成时间；预约查询始终再次查实时台账。

## 5. 选定四项创新功能

- **创作装备清单**：收藏设备、按场景归集、导出自己的清单；不默认收藏全库。
- **场景组合推荐**：校园采访、课堂演示、轻便Vlog、户外航拍、直播、实验记录6种组合。依据用途与兼容字段推荐；逐件显示目标时段是否可借，逐件预约。批量原子预约另行评估，不用成功一件冒充整套已约。
- **预约成就**：创作启程（首次保存成功）、三次启程（第三次真实成功预约）、跨类别探索者（不同类别预约）。这是预约成就，不声称已经实际使用三次；历史保留并说明解锁依据。
- **本地提醒**：即将开始、时段已结束、收藏设备当前可预约。只在应用运行时计算，未授权系统通知也可用站内提醒；不是后台推送或邮件服务。

预约成功仪式是基础体验：打勾 + 行程卡片 + 查看我的预约 + 基于兼容台账的配套设备建议，不把它做成全屏庆祝或强制弹窗。

## 6. AI产品体验与可信度

保留 YOSHUB_API_KEY / YOSHUB_BASE_URL / YOSHUB_MODEL 后端配置方式、超时、限流、有限重试和六部分周报校验。
助手卡片按“结论 → 数据依据 → 推荐行动”呈现，显示真实统计窗口；快捷问题不自动请求或预取，用户触发才调用。
“哪些设备适合采访 / Vlog套装”等新意图必须增加明确的场景解析契约并用真实台账核对，不能仅改快捷按钮文案让旧解析器假装支持。
阶段 B/C 扩充设备时同步参数化现有AI台账输入，保持原有查询与周报正确；阶段 D 再升级卡片、场景意图和统一反馈。
新增投影设备后，“无等效替代”的原三设备场景仍需测试，但产品答案必须根据当时真实可用的投影设备变化。

## 7. PWA / 跨端扩展边界

本轮拆分视图、组件、状态与API客户端，业务逻辑留在服务端服务层；避免依赖页面DOM才能调用预约规则。
预留 manifest 与应用图标、应用外壳缓存的接入点。正式离线/PWA安装属于后续工作，不在A阶段添加。
未来 Service Worker 只缓存可公开静态外壳；不缓存.env、AI响应或个人预约接口，不离线排队提交预约。离线时展示明确不可确认状态，恢复网络后重新查空闲。

### 验收与测试原则

每阶段原业务测试继续运行；新增测试覆盖该阶段新增行为。自动测试使用mock，真模型脚本不加入CI。
新测试重点：轮播暂停/焦点/减弱动画、请求失败无成功动画、字体持久化、维护设备拒约、账号数据隔离、重复seed、数据库重启恢复、取消后重约、推荐兼容性、提醒去重。
响应式检查四宽度，检查横向溢出、文字可读性、导航可触达、弹窗、表单、三档字号和200%浏览器缩放。性能检查素材大小、页面切换、轮播与滚动；指标在真实运行后记录，不预填分数。
