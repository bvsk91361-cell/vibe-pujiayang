
打开 http://localhost:3003 。构建把 `public` 放入 `dist`，复制唯一的业务规则模块 `src/booking.js`，并加入浏览器存储标记。`dist` 被 Git 忽略，避免源码仓库与发布产物混杂。

## 发布步骤

1. 源码先跑 `npm test`、push 功能分支，检查 Course CI 真正通过后合并。
2. 运行静态构建，把 dist 中的页面、脚本、样式、vendor 和 .nojekyll 复制到单独的发布 checkout。
3. 本次发布 checkout 为 `E:/桌面/vibecode/pages-output`，分支 gh-pages，远程为本人 GitHub 镜像仓库。
4. 在发布 checkout 检查 diff，commit，然后 `git push origin gh-pages`。不要 force push，也不要把本机 .git、私钥或预约数据复制进去。
5. GitHub 仓库 Settings → Pages 的源为 gh-pages / root。观察 pages build and deployment 的 success，再打开公网地址复验。main 源码的 push 不会自动重建这条发布分支。

官方配置说明：https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site
