# 两组真实工作闭环摘要

记录来源：本次 Codex 聊天与实际工具输出；补做日期 2026-10-07。以下为按任务重组的完整闭环摘要，不是 Trae 会话导出或逐字会话全文，也没有编造新的用户提示词。

## A：HTTP 中文姓名乱码 → 修复 → 通过

真实用户要求：“所有流程你都审计报告都让我一个人来完成就行”。

AI 对 `server.js` 进行审计，发现循环 `body += chunk` 对每个 Buffer 单独解码，中文可能跨块。新增最小 HTTP 用例：在“蒲”的 UTF-8 字节中间切开请求，分两次发送。首次实际失败：`'���嘉洋' !== '蒲嘉洋'`，原始输出在 `docs/验收证据/审计-中文分块修复前.txt`。

AI 在聊天中报告发现、说明修改文件，随后改成累计原始 Buffer、按实际字节限制 8192，最后 `Buffer.concat(chunks).toString('utf8')` 一次解码。再次真实执行 `npm test`，11 组全部通过；日志在 `审计-修复后测试.txt`，修改提交 `0cdf868`。对应云端 CI 37564369479 也实际成功。

## B：线上资源/预览适配 → 返工 → 页面闭环

真实用户要求：“然后你还要补齐前五天的审查，因为老师都要一个个检查”。

AI 对照第 4 天要求补公网演示与 CSV 能力。先审查原入口，发现 `/app.js` 这样的绝对路径不适合 `/vibe-pujiayang/` 项目站点，改成相对路径。用 Windows Python HTTP 服务预览时，实际页面只有静态布局，卡片、日期和列表没有初始化；读取响应头发现 JS 是 `Content-Type: text/plain`。

AI 增加 Node 预览脚本，显式返回 `text/javascript`，重新打开 `http://localhost:3003/`：卡片正常加载，预约成功、重复拒绝、刷新保留都实际观察到了。之后真正部署 GitHub Pages，在公网重复执行三张卡片选择、预约、重复拒绝与刷新保留。截图在 `docs/验收证据/公网表单预约与刷新.png`。CSV 的中文、引号、逗号、换行与公式防护通过组件测试；页面显示导出完成，但内嵌浏览器没有返回下载事件，因此不冒充已经核对了磁盘下载文件。

## 两次返工得到的习惯

先确定错误在哪个边界，再用最小用例固定它：一次在 HTTP 字节边界，一次在部署路径/MIME 类型边界。用可复现的失败与可观察的通过支持结论，不把“AI说好了”当作验收。
