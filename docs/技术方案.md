# 技术方案

- Node.js 22 内置 HTTP 服务，零第三方运行依赖；前端为 HTML、CSS、原生 JavaScript。
- `public/` 管页面；`src/booking.js` 管输入校验与冲突规则；`src/store.js` 管 JSON 持久化与写入队列；`server.js` 管接口。
- 预约模型：`id / name / equipmentId / date / slot / createdAt`。
- 接口：`GET /api/equipment`、`GET /api/reservations`、`POST /api/reservations`、`DELETE /api/reservations/:id`。
- 重复校验与写入在同一队列里执行，避免两个请求同时检查到空时段后都写入。
- 日期采用本地日历日；拒绝自动归一化的无效日期，比如 2 月 30 日。
- JSON 先写临时文件，再替换原文件。数据目录不进入 Git。
- 前端展示用户输入时使用 `textContent`，不拼入 HTML。
- 内置 `node:test` 验证业务规则、真实 HTTP 接口、持久化、取消和并发；CI 必须真实运行，不用静态绿灯冒充结果。

## 局限
单进程原型。多进程部署需要数据库唯一约束替代内存队列。公网正式使用前需补身份认证、取消权限、访问限制和运维备份。
